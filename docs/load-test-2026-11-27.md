# 2026-11-27 团队问答与入库压测

## 环境

- 本机 Windows，user-api Java 21，MySQL 8.4，Redis 7（`VECTOR_STORE=hash`）。
- AI 使用 `scripts/mock-ai.mjs`（OpenAI 兼容 mock chat/embedding/rerank），不消耗外部 API。
- 团队问答脚本：`scripts/load-test-team.mjs`；入库脚本：`scripts/load-test-import.mjs`。
- 这组数据只验证并发、配额预留、锁和 SSE 链路，**不代表真实 DeepSeek/BGE 的延迟、限流和成本**。

## 入库并发

```text
CONCURRENCY=5 TOTAL=20 node scripts/load-test-import.mjs
```

| 指标 | 结果 |
|---|---|
| 唯一 URL 入库 | 20 / 20 成功，HTTP 200 |
| p50 / p95 | 3,684ms / 4,532ms |
| 吞吐 | 约 1.2 次/秒（mock embedding 单次约 2–4s） |
| 同一 URL 5 并发 | 1 × 200、4 × 40904、0 × 5xx |
| 服务器错误 | 0 |

结论：单文章锁生效，并发重复入库返回 409 而不是 500/重复切片；唯一 URL 并发入库没有失败。

## 团队问答并发

```text
VUS=5 DURATION=10s node scripts/load-test-team.mjs
```

| 指标 | 默认限流 10/min | 限流调高到 10000/min |
|---|---|---|
| 请求 | 21 | 15 |
| 200 | 10 | 15 |
| 带引用 | 10 | 15 |
| 429 | 11 | 0 |
| 5xx | 0 | 0 |
| p50 / p95 | 292ms / 7,023ms | 3,825ms / 5,859ms |
| 吞吐 | 2.1 次/秒 | 1.5 次/秒 |

结论：

- 默认 `chatRateLimitPerMinute=10` 时，超过 10 次/分钟的请求按预期返回 429，没有 5xx。
- 调高限流后 5 VUs 全部成功并产生引用；mock 模型下 p95 约 5.9s，主要耗时在 mock embedding/chat 的固定延迟。
- 团队配额、个人配额、全站预算和预留流水在并发下未出现 500；结束后用量与 `ai_usage` 一致。

## HNSW 团队范围

本地 Redis Stack 验证：

- 预置一个 768 维、缺少 `team_id` 的旧索引；启动 `VECTOR_STORE=redisearch VECTOR_BACKFILL=true` 后自动重建为 1024 维并包含 `team_id`。
- 共享资料后 chunk hash 写入 `team_id` 和 `vector_bin`，`FT.SEARCH @team_id:{id}` 可以召回。
- 团队范围流式问答返回引用；索引异常/回填未完成时回退 pipeline。
- CI 的 `hnsw-integration` job 使用 `redis/redis-stack-server:7.4.0-v8` 自动回归。

## 仍未覆盖

- 真实 DeepSeek/BGE 的延迟、限流、错误率和成本。
- OCR（Tesseract）大批量扫描。
- 真实书签批量抓取（外部网站可达性、反爬和超时）。
- 生产规模 HNSW（百万级切片、索引重建时间、内存占用）。
- 公网 HTTPS、真实 SMTP、真实用户语料评测仍需外部资源。
